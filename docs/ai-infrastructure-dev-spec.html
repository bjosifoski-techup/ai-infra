Technical Specification

Emerico AI Infrastructure

LiteLLM proxy, eight MCP servers via Zuplo, MongoDB Atlas conversation memory, and a dedicated Keycloak instance for customer identity. This document is for the engineering team and excludes commercial terms.

Client: Emerico AI Sdn Bhd   ·   Engineering reference

Overview

Project Summary

A separate infrastructure engagement that extends the Emerico AI Commerce Platform with three components. LiteLLM is deployed on Elestio managed cloud and connected to the client's self-hosted LLM, with Keycloak JWT authentication and per-tier rate limiting. Eight MCP servers are configured via the Zuplo API gateway covering three dropshipping partners and five travel and ticketing affiliate partners, with tools auto-generated from OpenAPI specs and rate limiting handled at the gateway layer.

MongoDB Atlas hosts short-term and long-term conversation memory layers, with all reads and writes scoped per user via Keycloak JWT. All three components share a dedicated Keycloak instance deployed on Elestio specifically for Commerce Platform customer identity, separate from the SSO project's realm.

Scope

Three Components

LiteLLM Proxy

Unified LLM gateway deployed on Elestio managed cloud. Validates Keycloak JWTs, enforces per-tier rate limits, maps RBAC from role claims, and routes requests to the client's self-hosted model.

MCP Servers via Zuplo

Eight MCP servers configured in Zuplo covering three dropshipping partners (AliExpress, BigBuy, CJDropshipping) and five travel/affiliate partners (Travelpayout, Ticketmaster, Eventbrite, Viator, StubHub). Tools auto-generated from OpenAPI specs where available.

MongoDB Memory

Atlas-hosted memory layer with short-term (sliding conversation window) and long-term (preferences, summaries, purchase history) schemas. All queries scoped by Keycloak JWT user ID.

Infrastructure

Hosting & Operational Setup

  • LiteLLM proxy deployed on Elestio managed cloud (one-click LiteLLM deployment)
  • Zuplo API Gateway hosting all 8 MCP servers with native MCP support
  • MongoDB Atlas cluster for memory storage with optimized indexes for user-scoped lookups
  • Keycloak JWKS endpoint integration across LiteLLM, Zuplo, and memory APIs
  • Per-user-tier rate limiting at LiteLLM and gateway level
  • JWT user scoping middleware enforced on every memory read and write
  • Environment-based configuration for all API keys, endpoints, and secrets
  • Security hardening across all three components (LiteLLM, Zuplo, memory APIs)

Rate Limiting

Per-Tier Rate Limits

LiteLLM enforces rate limits per Keycloak user tier. RBAC is mapped from Keycloak role claims.

Guest

Lowest LiteLLM rate limit ceiling.

Free

Higher rate limit, registered user.

Silver

Paid tier with elevated rate limits.

Gold

Paid tier with high rate limits.

Platinum

Paid tier with the highest rate limits.

Important

Notes & Dependencies

Dedicated Keycloak instance

A fresh Keycloak instance is deployed on Elestio specifically for this infrastructure. It is separate from the SSO project and manages Commerce Platform customer identity only.

MCP tool complexity depends on OpenAPI spec quality

Partners with clean OpenAPI specs allow auto-generated tools. Partners without will require manual tool definition. Build order within Phase 3 should prioritize partners with the cleanest specs first to surface effort variance early.

Zuplo plan tier

Zuplo plan must support MCP server features. Confirm plan tier before Phase 3 begins.

Independent codebase

This engagement does not depend on the Emerico AI Commerce Platform codebase. Components can be developed, deployed, and tested independently and integrated into the Commerce app via configured endpoints.
