Technical Specification

Emerico AI Commerce Platform

An AI chat interface and traditional e-commerce storefront in a single Next.js app on Vercel. This document is for the engineering team and excludes commercial terms.

Client: Emerico AI Sdn Bhd   ·   Engineering reference

Overview

Project Summary

A Next.js application deployed on Vercel combining an AI-powered chat interface and a traditional e-commerce storefront into a single seamless experience. The app connects to a GCP-hosted AI agent backend via the AG-UI protocol over SSE, integrates three dropshipping partners for live product data, and handles full e-commerce operations through Openfront and Openship.

Two separate payment flows live side by side: Stripe for subscription billing and PhotonPay for product checkout. A five-tier user system plus admin, with rate limiting synced to the AI backend per tier, governs access and AI request quotas.

Infrastructure

Hosting & Operational Setup

  • Vercel hosting (Next.js, Edge Runtime, serverless API routes)
  • Edge Runtime for all SSE/streaming routes to avoid serverless timeout limits
  • Vercel KV or Redis for session and rate limit tracking
  • Secure HttpOnly cookies for refresh tokens
  • Short-lived JWT (5-10 minute TTL) for SSE authentication
  • Webhook endpoints for Stripe and PhotonPay event handling
  • Environment-based configuration for all API keys and secrets
  • AliExpress go-live audit compliance build

Access

User Tiers

Five customer tiers plus an admin role. AI request limits are enforced server-side and synced to the GCP backend per tier.

Guest

Limited AI requests (~5/day), full storefront access.

Registered Free

More AI requests (~50/day), full storefront, no payment required.

Silver Paid

Paid Stripe plan, higher AI request limit, specific LLM model.

Gold Paid

Paid Stripe plan, higher AI request limit, different LLM model.

Platinum Paid

Paid Stripe plan, highest AI request limit, premium LLM model.

Admin

Full access, MFA required. Manages users and their subscriptions (view, change plan, cancel, view billing status), plus Openfront and Openship.

Build

Scope of Work

Five workstreams organized by build order. Within each phase, items are independent unless noted.

1
Foundation, Auth & User System
  • Next.js project setup with Vercel deployment pipeline
  • Five-tier user registration and login system
  • MFA implementation for customers and admin
  • Session management with secure HttpOnly cookies and refresh token rotation
  • Short-lived JWT generation for SSE authentication
  • Admin dashboard login covering Openfront and Openship access
  • User registration sync to GCP AI backend (rate limit provisioning) and Openfront (cart/order identity), with retry and compensation logic for partial failures
  • Stripe subscription plan setup (Free, Silver, Gold, Platinum) with webhook handling for upgrades, downgrades, and cancellations
  • Subscription tier change sync to GCP AI backend
2
AI Chat Interface
  • AG-UI TypeScript SDK integration
  • Custom SSE connection to GCP AI backend via Edge Runtime
  • Short-lived JWT auth on every SSE connection with automatic refresh
  • Streaming response rendering in chat UI per Figma design
  • Chat history management and session continuity
  • Rate limiting enforcement per user tier against GCP backend limits
  • Add to cart action triggered from AI chat response (calls Openfront GraphQL)
  • Product link and metadata rendering inside chat responses
  • Security hardening of SSE layer (token expiry, abuse prevention, session binding)
3
Traditional Storefront & Dropshipping
  • Two-tab layout implementation per Figma design (AI Chat + Storefront)
  • Live product feed integration from AliExpress Open Platform API
  • Live product feed integration from CJDropshipping API
  • Live product feed integration from BigBuy REST API
  • Product listing, filtering, search, sorting across all three sources
  • Product detail pages with images, pricing, variants, shipping info
  • Unified product display layer abstracting the three different API response formats
  • Add to cart from storefront calling Openfront GraphQL
  • AliExpress audit compliance check across all product display and integration points
4
Cart, Checkout & Payments
  • Full cart management via Openfront GraphQL (add, remove, update quantities)
  • PhotonPay checkout integration for product purchases with sandbox testing
  • Payment confirmation webhook handling and order status updates
  • Order creation and sync to Openship for fulfillment
  • Returns, refunds, disputes, chargebacks flow via Openfront
  • Order history and tracking per customer account
  • Stripe checkout and billing portal for subscription management
  • Error handling and edge cases across both payment flows
5
UI Polish, Admin, Testing & Deployment
  • Full Figma design implementation across all screens
  • Admin panel: user management, subscription management (view, change plan, cancel, view billing status per user), Openfront and Openship access
  • End-to-end testing of all user flows across all five tiers
  • SSE streaming stability and timeout testing on Edge Runtime
  • Multi-system sync stress testing (registration, subscription changes)
  • PhotonPay live credential swap and final checkout testing
  • AliExpress audit preparation and submission
  • Production deployment, environment hardening, final QA

Modules

Additional Build Modules

  • Real-time toast alerts for key events
  • Events: order updates, payment confirmations, subscription changes, refund status updates, admin alerts for disputes and failed payments

  • Admin UI for managing markup rules across all dropshipping sources (AliExpress, BigBuy, CJDropshipping)
  • Global default markup with per-supplier, per-category, and per-product overrides; percentage or fixed amount
  • Same markup rules applied to both the traditional storefront and MCP tool results returned in AI chat
  • Live preview of marked-up prices against current supplier feeds
  • Audit log of markup changes with timestamp and admin user

Important

Notes & Dependencies

Soft dependency on partner environments

Build assumes Openfront, Openship, and the GCP AI backend become accessible for live testing. Development proceeds against API specs in the interim, but live integration testing requires their environments to be ready.

PhotonPay live credentials

Live credentials are needed before go-live. Sandbox is used during development.

AliExpress audit

AliExpress runs their audit as a post-build review process. It is outside the development workstream and handled separately.

Figma covers all screens

UI implementation assumes the Figma file covers both the AI chat surface and the storefront tab. Confirm storefront design is included before kickoff.

Marketing email scope

Marketing email scope covers transactional and lifecycle emails only. Full campaign management tools (bulk newsletters, drag-and-drop builders) are not in scope.
